# 見どころ候補生成 実験評価

評価日: 2026-07-28
実験ブランチ: `experiment/llm-highlight-candidates`

## 結論

ローカルLLMを使い、要約済みの章から見どころを選び、元のASRセグメント境界へ安全に戻す一連の処理は実装できた。候補の発見と編集開始位置の提案には利用できる。一方、長い独話を指定時間内で自然に完結させる品質はまだ安定していないため、無人での自動切り抜き・自動保存には使わず、候補をプレビューして人が確定する実験機能として扱う。

## 実装した処理

1. 保存済み章のタイトル・要約・タグだけで候補章を順位付けする。
2. 選ばれた章の元ASRから、LLMが中心となる単一セグメントIDを選ぶ。
3. アプリ側が最大時間内の許可窓を計算する。
4. LLMは許可窓内の実在セグメントIDだけで開始・終了を選ぶ。
5. アプリ側で順序、中心区間の包含、時間上限、元ASRとの対応を検証する。
6. 直前・直後の文脈を最大2回確認し、収まる場合は境界を拡張する。収まらない場合や文の継続が疑われる場合は警告を保存する。
7. 重複候補を抑制し、候補プレビューと直感編集への読み込みを提供する。自動保存はしない。

LLMには時刻を生成させず、最終的な時刻は常にSQLite内の元ASRセグメントから解決する。入力文字起こし中の命令文は信頼しないようプロンプトでも明示している。

## 評価方法

### 構造・時間境界

インデックス内の全動画を対象に、各動画から均等に5地点を選び、LLMを使わない決定的な境界計算を実行した。

| 指標 | 結果 |
|---|---:|
| 対象動画 | 14本 |
| 元ASRセグメント | 10,013件 |
| 評価アンカー | 70件 |
| 境界計算失敗 | 0件 |
| 最小時間未満 | 0件 |
| 隔離した不正ASR | 3件 |
| 候補長 最小 / 中央 / 最大 | 20.16秒 / 35.43秒 / 71.00秒 |

不正ASRは2動画に含まれていた。ゼロ以下の長さなどを持つ3件だけを隔離し、動画全体は処理対象として維持した。欠損時刻の補間や推測は行っていない。

### LLMによる候補品質

ローカルOllamaの `qwen3:8b` を使い、解析済みの異なる3動画から4候補ずつ生成した。動画名、文字起こし本文、内部IDは評価書へ保存していない。

| 指標 | 結果 |
|---|---:|
| 対象動画 | 3本 |
| 生成候補 | 12件 |
| 元ASRへ完全にリンク | 12件 |
| 最小時間未満 | 0件 |
| 自動境界拡張 | 10件 |
| 境界確認警告 | 9件 |
| 候補長 最小 / 中央 / 最大 | 45.70秒 / 86.14秒 / 89.27秒 |

題名と候補内容は、要約だけではなく、許可窓内で実際に選んだASR本文から生成する方式にしたことで初期版より対応が改善した。境界拡張を使い切った後の再確認を加えると、同じ12候補の警告は11件から9件へ減った。ただし、最大90秒に近い候補が多く、話が長く続く動画では直前の前提または結論を時間内に収められない。警告率が高いのはこの制約を隠さず検出しているためでもあるが、現状の候補をそのまま完成クリップとみなせないことを示している。

この結果を受け、既定の最大尺を180秒へ変更した。これは全候補を長くする目標値ではなく、
境界確認で必要と判定した発話を追加する余地を広げるハード上限である。上記の表は90秒設定時の
履歴として保持し、180秒設定の品質は候補長・境界警告数・人手での完結性を別runで再評価する。

## 採用判断

実験機能として継続する。用途は「見どころを探す時間を短縮し、その候補を編集画面で開く」までとする。

- 採用できる点: ローカル完結、実在ASR境界、時間上限、異常データ隔離、失敗の記録、手動確認への導線。
- 未採用の点: 自動保存、自動公開、警告なしの完成クリップ生成、要約だけからの時刻推定。
- 次の評価課題: 人手による候補有用性評価、文境界モデルまたは句読点復元の比較、短い発話単位を再構築した場合の警告率比較。

## 追加評価: 自然言語クエリ

要約済みの1動画を対象に一般的な自然言語クエリを入力し、正規化文字一致とBGE-M3意味検索から4候補を生成した。動画名、クエリ本文、検索結果本文は評価書へ保存していない。

- 生成候補: 4件 / 要求4件
- 元ASR segmentへ完全にリンク: 4件
- 最小尺未達: 0件
- 候補尺 最小 / 中央 / 最大: 24.22秒 / 36.67秒 / 55.37秒

WebUIのHTTP callbackでも同じクエリ生成経路が完了することを確認した。候補の個別・一括保存は合成出力を使った自動testで、partialからの置換、複数ファイル生成、partialとclaimの後片付けを確認した。実動画の完成品質は、利用者が候補をプレビューした上で別途評価する。
